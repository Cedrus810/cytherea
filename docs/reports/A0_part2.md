## 方法要点（实现时定下的）

- **Milestone 是区域，标签取“最后访问的 milestone”**，即 core-set milestoning。`milestone_of(obs)` 把一行观测映射到 transient 名、吸收态名或 None。每次换到另一个 milestone 记一次 hit，同时记一条转移；第一次进入吸收态时，轨迹结束。
- **Milestone 宽度本身就是模型误差**。1D 双阱数值试验（势垒 2 kT，dt = 1e-3，12 个 slab）：半宽 0.02 时，网络 committor 偏差 < 0.01；半宽 0.05 时偏差达 0.04，是一条反对称的“压平”曲线。改用“越过分界面”定义的 milestone，在离散观测下会因越界（overshoot）偏差 0.024，更差。所以算例的 slab 半宽取 0.02，约半个 rms 步长。11.4 标签 (1,1) 残差的反对称形状（左 +0.011，右 −0.011）就是这一项。
- **读 WE 记录**一律用 `segment_own_rows`，沿 `parent_digest` 把标签传给子段；已吸收段的子段忽略，recycled walker 视为新轨迹，缺失的父段直接报错。
- **直接估计**（Markov 检验的对照量）：一次 hit 的结局向量取它所在段的未来，G(s) = Σ_c (w_c/w_s) G(c)。split、merge 都保持 E[G] 不变；被 merge 掉的 walker 没有子段，它的权重由幸存者带着。估计量以“已吸收”为条件，未吸收的权重比例另行报告（这里 < 1e-4）。
- **Markov 检验按 (origin label, milestone) 分层比较**。只在合并后的直接统计量上比较是查不出标签记忆的：合并网络和合并直接统计量都是同一个标签混合。数值试验里两者只差 0.03，与噪声同量级。分层比较时，合并网络对两个标签给出同一个预测，与各标签直接值的差达 0.2（离散链试验），11.3 实测为 0.124。这正对应设计 4.5 第 1 点。
- **统计量与阈值**：D = max |B_net − B_dir|。bootstrap 的独立单位是 WE run（同一 run 内的 walker 被重采样耦合），训练集和留出集都重算，并以观测差为中心（与 CK 检验的 R23 做法相同）。D ≤ D* 的 95% 分位数即通过。在真正 Markov 的离散链上，30 个种子 30 个通过，所以这个检验略偏保守。

| | RMSE | 噪声期望 | 最大残差 | Markov 检验 |
|---|---|---|---|---|
| 11.2 dw2d | 0.0130 | 0.0064 | +0.023（m5） | 未通过（诊断，见下） |
| 11.4 标签 (1,1)，势垒 1 kT | 0.0101 | 0.0061 | ±0.013 | 通过 |
| 11.4 标签 (2,2)，势垒 4 kT | 0.0016 | 0.0067 | −0.003 | 通过 |

- 参考解：dw2d 是可分离势，用 1D 精确积分。channel 用二维有限体积解，在 (x_m, y0 = ±1) 处取值；网格 n = 200 和 n = 400 之间最大差 0.0018。
- 数据量：每个算例 96 个 WE run（训练 48、留出 48）。dw2d 共 34.4 万段，每个 run 15 s；channel 共 67.3 万段，每个 run 31 s。噪声期望是在 run 层面 bootstrap 得到的 q_net 方差的均方根。

### 偏离计划：run 数从 24 + 24 提高到 48 + 48

第一次运行时每个算例是 24 + 24 个 run，三项全部通过，但 11.2 的 RMSE 为 0.0256，离阈值只差 0.004。排查过程如下：

- 网络 committor 和留出数据的直接估计一致（m5：0.454 对 0.455），两者一起偏离参考解。所以问题不在网络方法，而在 WE 数据本身。
- 起点关于 x = 0 对称，因此整体 P_B 的精确值为 0.5。这个 campaign 实测 0.5204 ± 0.0077（+2.6σ）。又用新种子重跑了三个同样的 48-run campaign，得到 0.4862 ± 0.0075、0.4861 ± 0.0065、0.4967 ± 0.0090，对应 RMSE 分别为 0.017、0.018、0.006。四个 campaign 合计 192 个 run，P_B = 0.4974 ± 0.0038，与 0.5 一致。去掉引发排查的那一个（存在选择效应），其余三个彼此一致（χ² = 1.1 / 3）。
- RNG 由 key 经 sha256 和 SeedSequence 派生，相邻种子之间没有相关性。

结论：WE 没有偏差。committor 曲线的误差主要来自 run 层面的整体涨落（单个 run 的 P_B 标准差为 0.053），24 + 24 个 run 时这项噪声相对阈值 0.03 余量不够，情况与 A0 part 1 的 9.2 相同。于是 run 数翻倍，种子规则和阈值都不变。

### 11.2 的 Markov 检验为什么没有通过

训练集用的种子是 `SEED + 0…47`，恰好就是上面那个 +2.6σ campaign 的全部 48 个 run（逐位复现）。留出集是新的 48 个 run。直接估计与参考解一致（m5：0.4253 对 0.422），网络则偏高（0.470），偏差的形状与 +2.6σ 的整体涨落一致：中间最大，向两端减小。dw2d 是可分离势，x 方向的 slab 在宽度误差之内是精确的 Markov milestone，所以这是一次 5% 水平检验的假阳性（p ≈ 3%），而不是非 Markov 效应。没有为了让它通过而改种子。

这件事对 Phase C 的启示：Markov 检验比较的是两组独立数据，因此 run 层面的整体涨落和非 Markov 性在统计量上无法区分。要下“milestone 太粗”的结论，需要失败的形状与之对应（例如按标签系统性地分开，如 11.3），或者换一组训练、留出划分后仍然失败。
